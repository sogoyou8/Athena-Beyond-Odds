# Error Handling

> **Version :** 1.0  
> **Statut :** Brouillon

---

## 1. Catégories

- validation ;
- authentification ;
- autorisation ;
- données ;
- fournisseur ;
- modèle ;
- IA ;
- paiement ;
- réseau ;
- système.

---

## 2. UX

Un message d’erreur doit :

- expliquer ce qui s’est passé ;
- indiquer l’impact ;
- proposer une action ;
- éviter le jargon ;
- conserver les données saisies ;
- fournir une référence si support nécessaire.

---

## 3. Données partielles

Afficher :

- ce qui est disponible ;
- ce qui manque ;
- depuis quand ;
- l’impact sur l’analyse.

---

## 4. IA

Si la réponse ne peut pas être fondée :

- ne pas inventer ;
- expliquer l’insuffisance ;
- proposer les données disponibles ;
- permettre de reformuler.

---

## 5. Backend

Chaque erreur possède :

- code stable ;
- message interne ;
- message public ;
- corrélation ;
- sévérité ;
- retry possible ;
- propriétaire.

---
